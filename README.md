# Living like a giraffe

[포트폴리오](https://livinglikeagiraffe.github.io/)는 Blender에서 계산한 조명과 반사를 실제 Three.js 공간에 표시합니다. 드래그로 공간을 이동하고 휠이나 핀치로 확대합니다. Home 키로 처음 위치로 돌아갑니다.

## 공간 편집과 공개

[Studio](https://livinglikeagiraffe.github.io/admin/)에서 GLB와 참조 PNG를 담은 ZIP, 원본 `.blend`를 올리고 버전을 저장합니다. Blender 파일에는 사용하는 텍스처와 외부 리소스를 포함합니다. 전체 씬 한 개가 격자의 한 모듈입니다. GitHub 쓰기 및 Actions 실행 권한을 연결하면 배치 저장 시 워커가 원본 씬을 조합하고 조명과 시점별 반사를 계산합니다. Blender와 웹 렌더의 시점별 검증을 통과한 현재 배치가 공개 공간으로 선택됩니다.

## 전송과 렌더링

워커는 검증용 GLB와 공개용 데이터를 함께 생성합니다. 공개 페이지는 메시, 확산광, 원본 색 변환 및 최초 시점에 필요한 반사를 먼저 받습니다. 첫 화면을 표시하면서 나머지 방향의 다운로드 진행률과 조작 방법을 안내합니다. 반사 텍스처를 디코딩하고 GPU에 올린 뒤 탐색을 시작합니다. 원근 카메라에서는 한 화면에 여러 방향의 광선이 필요해 전체 반사를 첫 묶음에 포함합니다.

공개 패키지는 유리·저거칠기 표면의 방향별 반사, 확산광, 색 변환표를 원본 정밀도로 보관합니다. 일반 표면의 방향별 반사만 RGBM 값을 다시 인코딩하며, 각 채널의 선형 광량 오차는 원래 값의 1% + 0.0006 이하로 제한합니다. 이 상한은 최종 화면의 색상 오차와는 다른 값입니다. 동일한 데이터는 SHA-256으로 찾아 공유합니다. 브라우저는 검증한 블록을 Cache Storage에 보관해 재방문 시 재사용합니다. 저장 공간이 부족하거나 캐시 사용이 제한된 브라우저도 다운로드로 탐색할 수 있습니다. 유리 재질에는 고해상도 방향별 베이킹과 선형 HDR 슈퍼샘플링을 사용합니다.

## 개발과 배포

Node.js 22 환경에서 `npm ci`, `npm test`, `npm run build`를 실행합니다. `python3 -m http.server 8080 --directory dist`로 배포본을 확인할 수 있습니다. Python 검사는 `python3 -m unittest discover -s tests`로 실행합니다.

GitHub Pages의 배포 원본은 GitHub Actions입니다. `Publish GitHub Pages` 워크플로는 공개 공간, Studio와 비교 도구를 포함한 `dist/`를 배포합니다. 현재 배치가 없는 경우 빌드에 포함한 검증된 v06 공간을 엽니다. 이전 포트폴리오의 소스와 렌더 기록은 저장소에 보관합니다.
