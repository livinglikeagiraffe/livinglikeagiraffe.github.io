# Living Like a Giraffe

기린과 함께 초원을 돌아다니며 ㅊㅊㅊ 운동회와 멘탈 사우나 프로젝트를 만나는 Three.js 웹사이트.

배포 주소: https://livinglikeagiraffe.github.io/

## 새 공간 프로토타입 (/v2/)

기존 `/`와 독립된 새 화면은 로컬 `http://127.0.0.1:4173/v2/`에서 확인합니다. 같은 빌드에 포함되므로 GitHub Pages 배포 시 `/v2/`로 제공됩니다. 현재 홈페이지의 메뉴나 진입 화면은 바꾸지 않습니다.

- 제공받은 `riraji_normal.glb` (약 4.2 MB)를 원래 배치·재질·Quarter_Camera 방향으로 표시합니다.
- 회전·확대, 처음 시점 복원, 제작자 참고 이미지 비교를 지원합니다.
- 웹용 환경광·주광·그림자·SSAO를 추가했습니다. 화면 변화가 있을 때만 렌더링합니다.
- 원본 `.blend`와 비교용 displacement GLB는 배포하지 않습니다. 원본에서 추출한 카메라와 Area Light 배치를 공유 뷰어에 적용합니다. 면광원·부드러운 그림자·SSAO·색조 보정을 결합한 근사값이며, Cycles 간접광·절차적 재질·Filmic 색 관리의 완전한 복원을 보장하지 않습니다.
- 제공된 `.blend`의 두 씬에 원본 카메라·소프트박스·보조광·실내 조명·배경판과 절차적 점토 재질이 저장되어 있습니다. Blender 3.6.23에서 Cycles, Filmic / Medium High Contrast, 1500×1200·40샘플 원본 재렌더를 검증했으며 누락된 외부 파일은 없었습니다. 웹 실시간 조명은 여전히 근사 구현입니다.

`v2/` 아래 파일과 에셋은 `scripts/build.mjs`에서 함께 복사합니다. 기존 사이트와 Three.js 배포 모듈을 공유하며 화면 스크립트와 스타일은 별개입니다.

## 관리자 작업실 (/admin/)

`npm start` 실행 후 `http://127.0.0.1:4173/admin/`에서 사용합니다. Pages 배포에도 같은 경로가 포함됩니다. 기존 홈페이지 `/`는 유지됩니다.

- ZIP과 `.blend`를 함께 선택하면 압축 안의 GLB·PNG를 선택해 비교합니다. 텍스처가 내장된 GLB를 지원합니다.
- 비교 화면 아래 접힌 ‘재질·조명’에서 밝기·주광·보조광·거칠기·요철·카메라를 조절합니다. 조정값 `webLook`은 새 버전에 저장되고 다시 불러옵니다. 원본 재질 텍스처와 유리의 투과 속성은 유지합니다.
- 원본 렌더의 `report.json.webScene`에는 glTF 좌표계로 변환된 카메라·조명 위치/방향/색/에너지와 원본 색 관리 정보가 포함됩니다. 렌더 완료 시 카메라·조명 배치를 자동 적용하며 ‘원본 설정으로 맞추기’로 다시 적용할 수 있습니다. 에너지는 웹용 근사 변환이며 색 관리 정보는 동일한 OCIO 재현을 의미하지 않습니다. 렌즈 시프트·파노라마·커스텀 셰이더는 완전히 재현하지 않습니다.
- 현재 첨부 씬은 실제 Blender에서 추출한 `v2/assets/scene-profile.json`을 GLB SHA-256이 일치할 때만 사용합니다. 새 파일은 GLB 카메라/기본 조명으로 시작하고 원본 렌더 후 해당 파일의 정보를 가져옵니다. `/v2/`도 같은 뷰어와 기본 조명을 사용합니다. 모듈 버전의 개별 조정값은 관리자 미리보기에 적용되며 `/v2/`의 고정 예제를 자동 교체하지 않습니다. 격자에서는 재질 조정값을 유지하고 씬 전체에 공통 조명을 씁니다.
- 전체 씬 한 개를 모듈 한 개로 취급합니다. 기본 격자 4×3, 칸 40×32m, 간격 2m이며 90도 회전과 크기 조정을 지원합니다. 모듈은 비율을 유지하고 칸을 초과할 때만 축소됩니다.
- 연결 전에는 IndexedDB에 버전·배치를 저장합니다. GitHub 연결 후에는 Git Data API로 파일과 manifest를 하나의 커밋에 저장하고 강제 푸시 없이 충돌을 재시도합니다.
- 원본 공개가 승인된 현재 사이트 저장소를 사용합니다. 공개 카탈로그는 로그인 없이 읽으며, 쓰기·렌더 요청에는 저장소 Contents/Actions 쓰기 권한 토큰이 필요합니다. 토큰은 페이지 메모리에만 보관합니다.
- 원본과 버전은 `studio/modules/<module UUID>/versions/<version UUID>/`에, 목록은 `studio/catalog.json`, 배치는 `studio/layout.json`에 저장합니다. 사이트 빌드에는 업로드 원본을 복사하지 않지만 공개 GitHub 저장소에서는 누구나 내려받을 수 있습니다.
- `render-module.yml`은 정확한 에셋 커밋의 파일 해시를 검사한 뒤 Blender 3.6.23 / Cycles CPU로 렌더링합니다. 빠른 미리보기는 긴 변 최대 800px·24샘플, 원본 설정은 저장된 렌더 설정을 유지합니다. 업로드된 Python은 자동 실행하지 않습니다.
- 렌더 작업과 저장 작업의 권한을 분리했습니다. 렌더 결과는 `studio/renders/<request UUID>/`에 커밋하므로 임시 Actions artifact 만료 후에도 보관됩니다. 작업당 90분 제한이며 실패 시 Actions 로그를 표시합니다.
- 업로드 제한: 파일당 48MiB, 압축 해제 합계 180MiB, 100개 파일. 경로 이탈·중복 경로·압축 해제 크기를 검사합니다. 저장소가 커지면 원본을 Releases나 전용 오브젝트 저장소로 옮기는 것이 좋습니다.

GitHub 설정 및 제작자 사용 안내: `admin/setup.html`. 성공한 최신 배치는 `/clay/`에 자동 반영됩니다. 기존 홈페이지 `/`와 `/v2/`의 고정 예제는 유지됩니다.

## 실행과 배포

```sh
npm ci
npm start
```

로컬: http://127.0.0.1:4173/

`npm run build`로 `dist/` 정적 사이트를 생성합니다. Node 서버는 로컬 개발용이며 호스팅 서버는 필요하지 않습니다. Three.js 의존 모듈, 실제 사용하는 모델/텍스처/미디어, 출처 파일만 배포합니다.

GitHub Pages: Settings → Pages → Source를 GitHub Actions로 설정하고, Actions → Publish GitHub Pages → Run workflow를 실행합니다. 배포 워크플로는 수동 실행으로 설정되어 있습니다.

## 조작

- 데스크톱: WASD/방향키 이동, Shift 달리기, R로 프로필 러그에 복귀.
- 모바일: 오른쪽 아래 조이스틱. 중앙 가까이는 걷기, 바깥쪽은 달리기.
- 프로젝트 근처: 프로젝트 보기 또는 E. 사진·영상 확대 및 좌우 넘기기 지원.

## 공개 전 최적화

배포 출력은 약 155 MiB (데스크톱·모바일 에셋 및 미리보기 합계)이며, 사용하지 않는 원본/예전 텍스처/검수 스크린샷은 제외됩니다. 잔디 텍스처 19.85 → 3.51 MiB, 주 기린 GLB 18.13 → 10.18 MiB. 모델 형태·스킨·애니메이션 데이터는 유지합니다. 모바일 픽셀 비율 상한 1, 그림자 512px을 적용합니다. 갤러리 이미지는 지연 로딩하고 데스크톱 영상은 보일 때만 음소거로 재생하며, 모바일 영상은 재생 버튼을 눌러야 로드·재생합니다.

`python3 scripts/optimize-assets.py`는 Pillow가 있는 개발 환경에서 선택적으로 재실행할 수 있습니다. 원본은 최초 실행 시 `.source-assets/`에 보관하며 Git/배포에는 포함하지 않습니다. 일반 빌드에는 Python이 필요하지 않습니다.

## 모바일 안정성

터치 기기 또는 처음 접속한 화면 너비가 650px 이하이면 모바일 에셋을 선택합니다. 같은 세션에서 창 크기를 바꿔도 고용량 에셋으로 전환하지 않습니다.

- 모바일 기린 텍스처 최대 2K, 주요 소품 512px. 모델의 형태·리깅·애니메이션은 동일합니다.
- 고밀도 화분, 주변 나무, 카세트, 작은 야구 소품은 모바일에서 요청하지 않습니다.
- 기린 → 공간과 순차 소품 → 친구 기린 → 셰이더 준비 순서로 로드합니다.
- 모바일 렌더링은 DPR 1, 그림자 512px, 최대 30fps이며 MSAA를 끕니다. 숨겨진 탭은 렌더링하지 않습니다.
- 모바일 3D 소스 텍스처의 RGBA+mipmap 추정 합계는 약 92MiB입니다. 포스터·렌더 타깃·모델·디코딩 메모리는 별도이며 실제 iPhone 전체 메모리 측정치는 아닙니다.
- 로딩 실패나 WebGL context loss는 재시도 화면으로 안내합니다. OS가 탭 프로세스를 종료하는 경우에는 브라우저 내부 메시지가 표시될 수 있습니다.

`python3 scripts/mobile-assets.py`로 모바일 에셋을 다시 생성할 수 있습니다(Pillow 필요). 생성된 에셋을 저장소에 포함하므로 배포 빌드에는 Python이 필요하지 않습니다.

공유 카드는 `assets/branding/share.png`, favicon은 같은 디렉터리에 있으며 공식 Instagram 프로필 이미지를 사용합니다.

## 상세 글 미디어 로딩

대표 포스터는 높은 우선순위로 디코딩한 후 3D 공간에서 상세 화면으로 전환합니다. 본문 미디어 요청은 전환 완료 이후에 시작합니다. 화면에 들어온 이미지만 160px 미리보기 → 최대 960px 본문용 이미지로 바꾸고, 확대 화면에서 원본을 요청합니다.

모바일 갤러리는 영상 대신 미리보기 이미지를 사용합니다. 확대 후 ‘영상 재생’을 누르기 전에는 MP4를 요청하지 않으며, 다음 영상도 자동 재생하지 않습니다. 가로 드래그는 갤러리에서 처리하고 세로 스크롤은 브라우저에 맡깁니다.

미리보기 재생성: `python3 scripts/gallery-previews.py` (Pillow 필요). `posts.json`의 preview/display 경로와 생성 파일을 함께 커밋합니다.

## Clay 페이지와 편집 스튜디오

기존 `/`와 `/v2/`를 유지하고 `/clay/`에서 v06 공간을 표시합니다. 드래그·터치 이동, 휠·핀치 줌, 방향키·+/−·Home을 지원합니다. 줌아웃할 때 높이와 각도가 조금 낮아지고 감속하며 정지합니다. 움직임 줄이기 설정을 따릅니다.

`/admin/` → GitHub 연결 → ZIP 선택 → 배치에 추가 → 배치 저장·베이킹. 저장되지 않은 모듈도 배치 저장 시 원본 파일과 함께 업로드됩니다. 전체 씬 하나가 한 모듈이며 내부 방의 상대 위치를 유지합니다. v06은 `full/`의 Normal GLB와 .blend가 우선 선택됩니다.

### 간접광 파이프라인

- `studio/compose.py`: 배치 스냅샷·원본 해시 검증, 전체 씬 합성, 공통 바닥·조명 구성.
- `studio/hybrid.py`: Cycles INDIRECT diffuse(색 제외), albedo, tangent normal, roughness를 각각 계산. 모든 아틀라스가 끝날 때까지 원본 재질을 유지합니다. UV 검증 실패 시 묶음을 이분해 재시도합니다.
- 간접광은 OIDN 후 선형 RGBM으로 저장합니다. OCIO 화면용 변환을 텍스처에 넣지 않습니다. GLB 재질 extras의 `studioLightMap`이 내장 PNG·UV·범위를 참조합니다. 웹 로더가 RGBM을 복원하고 pi를 곱해 조도 입력으로 사용합니다.
- `clay/materials.js`: PBR 재질·직접광·표면 노멀을 유지하고 작은 절차적 클레이 요철을 추가합니다. 베이킹된 간접광과 환경의 확산광을 중복 계산하지 않습니다. 면광원과 반사·굴절은 웹에서 근사합니다.
- 표준 2K·96샘플 / 정밀 2K·256샘플. 불투명 메시를 아틀라스별로 합쳐 그리기 호출 수를 줄입니다. 유리·금속·발광 재질은 별도로 유지합니다.
- 기존 `studio/bake.py`의 Combined/unlit 결과도 이전 버전 검수용으로 계속 지원합니다.

### 버전과 공개

GitHub Actions `render-module.yml`이 `mode=hybrid`, `kind=layout`으로 실행됩니다. `studio/layouts/<id>.json`은 고정 배치, `studio/renders/<request>/`는 결과입니다. `studio/save_result.py`는 결과 SHA-256을 검사하고 **현재 배치와 ID·digest가 일치하는 성공 결과만** `studio/public-scene.json`에 연결합니다. 오래된 작업이 늦게 끝나도 최신 배치를 덮어쓰지 않습니다. 저장 충돌 시 최신 브랜치에서 공개 조건을 다시 검사합니다.

`/clay/`는 현재 저장소의 공개 포인터를 읽고 GLB 해시를 검증합니다. 새 배치가 계산 중이면 이전 완료 결과를 유지합니다. 원본 .blend는 저장소에 보관하고 Pages 산출물에는 넣지 않습니다. 소스 변경 시 Pages를 배포하며, 이후 배치 베이킹 결과는 별도 Pages 재배포 없이 반영됩니다. 저장소가 공개이므로 방문자가 토큰 없이 결과를 읽습니다.

### 검증과 한계

`npm test`, `PYTHONPYCACHEPREFIX=/tmp/giraffe-pycache python3 -m unittest discover -s tests -p 'test_*.py'`, `npm run build`.

Blender 검증: `blender --background --factory-startup --disable-autoexec --python-exit-code 1 --python studio/render.py -- --manifest studio/layouts/<id>.json --output <directory> --kind layout --mode hybrid --quality preview`.

최대 6모듈, 원본당 4,000메시, 전체 12,000메시·300만 삼각형, GLB 48MiB, 90분. 실제 처리 가능 범위는 UV·재질 복잡도에 따라 달라집니다. Cycles의 임의 셰이더와 모든 조명 효과를 실시간 웹에 1:1 재현하지는 않습니다. 구조나 조명이 바뀌면 전체 간접광을 다시 계산해야 합니다.
