CONNECTED WORKSPACE

GitHub를 작업실의 보관함으로.

Pages는 화면을 제공하고, 저장소는 원본·버전·격자 배치를 보관합니다. Blender 렌더는 GitHub Actions에서 실행됩니다. 상시 서버는 필요하지 않습니다.

1. 저장소 준비

원본을 공개하지 않으려면 별도의 비공개 저장소를 만들고 기본 브랜치에 README 파일을 하나 추가하세요. 관리자 화면은 기존 Pages에 두어도 됩니다. 공개 저장소에서는 .blend를 포함한 모든 업로드 파일과 과거 버전이 공개됩니다.

2. 렌더 워크플로 설치

선택한 저장소의 기본 브랜치에 다음 두 파일을 넣습니다.

  • render.py 다운로드 → studio/render.py
  • render-module.yml 다운로드 → .github/workflows/render-module.yml

워크플로는 Blender 3.6.23과 Cycles CPU를 사용합니다. 대기 중인 작업은 GitHub의 동시 실행 정책을 따르며, 실행당 제한 시간은 25분입니다. 빠른 미리보기는 최대 긴 변 800px·24샘플, 원본 설정은 저장된 해상도·샘플·카메라·색 관리를 사용합니다. 자동 스크립트 실행은 꺼져 있습니다. 외부 파일은 .blend 안에 패킹해 주세요.

3. 접근 토큰

GitHub Settings → Developer settings → Personal access tokens → Fine-grained tokens에서 해당 저장소만 선택하고 Contents: Read and write, Actions: Read and write 권한을 부여합니다. 워크플로 파일 설치는 GitHub에서 직접 수행하므로 앱의 토큰에 Workflows 수정 권한은 필요 없습니다.

이 작업실은 토큰을 현재 페이지 메모리에만 보관합니다. 토큰을 코드에 넣거나 커밋하지 마세요. 새로고침 후에는 다시 연결해야 합니다. 제작자도 저장소 협업 권한과 각자의 토큰을 사용합니다. 간편한 GitHub 로그인은 별도의 OAuth/GitHub App 인증 중계가 필요하므로 현재 버전에 포함하지 않습니다.

4. 작업 흐름

  1. ZIP·GLB·PNG·.blend를 선택합니다. 이 단계는 브라우저 안에서만 처리됩니다.
  2. GLB·참고 이미지·Blender 원본을 선택하고 모듈 이름을 정합니다.
  3. GitHub 연결 후 버전 저장을 눌러 원본과 렌더 입력을 기록합니다.
  4. 원본 렌더 요청을 누르면 Actions가 실행됩니다. 결과는 저장소의 studio/renders/에 남습니다.
  5. 저장한 버전을 격자에 추가하고 배치 저장을 누릅니다.

연결하지 않은 상태의 버전·배치는 IndexedDB에 저장됩니다. 해당 브라우저 데이터 삭제 시 사라질 수 있으므로 장기 보관하려면 GitHub에 저장하세요.

모듈 규격

전체 GLB 씬 한 개가 모듈 한 개입니다. 기본 칸은 40×32m, 간격은 2m, 격자는 4×3칸입니다. 크기와 칸 수를 조정할 수 있으며 회전은 90° 단위입니다. 모듈은 바닥 중앙을 기준으로 놓고, 칸을 넘을 때만 균일하게 축소합니다. 모델의 가로·세로 비율을 바꾸거나 내부 방을 분리하지 않습니다.

보관·공개

파일당 48MiB, 한 번에 압축 해제된 파일 180MiB·100개까지 지원합니다. 렌더 결과는 임시 Actions artifact에서 저장소로 복사되므로 artifact 만료 후에도 남습니다. 현재 사이트 빌드는 관리자 코드만 포함하며, 업로드 원본·버전·격자 배치는 자동으로 공개 포트폴리오에 반영하지 않습니다. 공개 버전 선택과 배포는 별도 단계입니다.

공개 저장소의 표준 GitHub-hosted runner는 무료이며, 비공개 저장소는 계정별 무료 사용량을 사용합니다. 실제 한도와 초과 과금 설정은 GitHub Billing에서 확인하세요.
