CONNECTED WORKSPACE

GitHub를 작업실의 보관함으로.

Pages는 화면을 제공하고, 저장소는 원본·버전·격자 배치를 보관합니다. Blender 렌더는 GitHub Actions에서 실행됩니다. 상시 서버는 필요하지 않습니다.

1. 저장소 준비

원본을 공개하지 않으려면 별도의 비공개 저장소를 만들고 기본 브랜치에 README 파일을 하나 추가하세요. 관리자 화면은 기존 Pages에 두어도 됩니다. 공개 저장소에서는 .blend를 포함한 모든 업로드 파일과 과거 버전이 공개됩니다.

2. 렌더 워크플로 설치

선택한 저장소의 기본 브랜치에 다음 네 파일을 넣습니다.

  • render.py 다운로드 → studio/render.py
  • bake.py 다운로드 → studio/bake.py
  • compose.py 다운로드 → studio/compose.py
  • render-module.yml 다운로드 → .github/workflows/render-module.yml

워크플로는 Blender 3.6.23과 Cycles CPU를 사용합니다. 대기 중인 작업은 GitHub의 동시 실행 정책을 따르며, 실행당 제한 시간은 45분입니다. 빠른 미리보기는 최대 긴 변 800px·24샘플, 원본 설정은 저장된 해상도·샘플·카메라·색 관리를 사용합니다. 자동 스크립트 실행은 꺼져 있습니다. 외부 파일은 .blend 안에 패킹해 주세요.

3. 접근 토큰

GitHub Settings → Developer settings → Personal access tokens → Fine-grained tokens에서 해당 저장소만 선택하고 Contents: Read and write, Actions: Read and write 권한을 부여합니다. 워크플로 파일 설치는 GitHub에서 직접 수행하므로 앱의 토큰에 Workflows 수정 권한은 필요 없습니다.

이 작업실은 토큰을 현재 페이지 메모리에만 보관합니다. 토큰을 코드에 넣거나 커밋하지 마세요. 새로고침 후에는 다시 연결해야 합니다. 제작자도 저장소 협업 권한과 각자의 토큰을 사용합니다. 간편한 GitHub 로그인은 별도의 OAuth/GitHub App 인증 중계가 필요하므로 현재 버전에 포함하지 않습니다.

4. 작업 흐름

  1. ZIP·GLB·PNG·.blend를 선택합니다. 이 단계는 브라우저 안에서만 처리됩니다.
  2. GLB·참고 이미지·Blender 원본을 선택하고 모듈 이름을 정합니다.
  3. GitHub 연결 후 ‘조명·그림자 베이킹 함께 생성’을 켜고 렌더 · 베이킹 요청을 누릅니다. 아직 저장하지 않은 입력은 자동으로 버전 기록을 만든 뒤 Actions를 실행합니다.
  4. 결과를 비교하고 버전 저장을 눌러 검수 결과를 새 버전으로 기록합니다. 렌더 PNG, 베이킹 GLB와 텍스처는 저장소의 studio/renders/에 남습니다.
  5. 저장한 버전을 격자에 추가하고 배치 저장을 누릅니다.

연결하지 않은 상태의 버전·배치는 IndexedDB에 저장됩니다. 해당 브라우저 데이터 삭제 시 사라질 수 있으므로 장기 보관하려면 GitHub에 저장하세요.

조명 베이킹

원본 렌더 뒤 Blender Cycles로 UV를 생성하고 불투명 표면의 색·직접광·간접광·그림자를 텍스처에 저장합니다. 노이즈 제거 후 원본 색 관리를 적용하며, 웹에서는 추가 조명과 색 보정을 중복 적용하지 않습니다. 빠른 미리보기는 1K·24샘플, 원본 설정은 2K·64샘플 베이킹입니다. 완료되면 베이킹 3D가 자동 표시되고 실시간 조명 버튼으로 비교하거나 GLB를 다운로드할 수 있습니다.

고정된 현재 프레임을 위한 기능입니다. 유리·투명 재질은 실시간 PBR로 남고 시점에 따른 반사는 원본과 다릅니다. 조명·구조를 바꾸면 다시 베이킹해야 하며, 별도로 구운 모듈 사이의 간접광·그림자는 합성되지 않습니다. 격자에서는 큰 촬영용 배경을 제외합니다. 볼륨·비메시 오브젝트·절차적 인스턴스는 먼저 메시로 정리해야 합니다. 최대 600개 메시·150만 삼각형·결과 GLB 48MiB를 지원합니다.

전체 공간 다시 베이킹

격자에서 ‘배치 저장 후 전체 공간 자동 베이킹’을 켜고 저장하면 각 모듈의 Blender 원본을 다시 조립합니다. 개별 촬영 배경을 제거하고 하나의 공통 바닥을 만들며, 첫 모듈의 큰 조명을 공간 전체에 맞춥니다. 작은 실내 조명은 각 모듈에 유지합니다. 전체 씬을 함께 계산하므로 모듈 사이 그림자와 간접광도 결과에 포함됩니다.

완료 후 편집용 3D·전체 베이킹 3D·Blender 렌더를 전환할 수 있습니다. 배치·회전·간격·바닥 색을 바꾸면 이전 결과는 오래된 것으로 표시되고, 다시 저장하면 새 기록을 만듭니다. 실패한 작업은 재요청할 수 있습니다. 배치 기록은 studio/layouts/, 결과는 studio/renders/에 남습니다.

1~6개 모듈, 총 1,800개 메시·150만 삼각형·GLB 48MiB까지 지원합니다. 각 모듈에 패킹된 Cycles .blend 원본이 필요합니다. 여러 씬이 있는 원본은 사용할 씬을 선택해 모듈 렌더를 먼저 완료하세요. 해상도는 모듈별 1K 또는 2K이며 조명 계산은 전체 공간을 함께 사용합니다. 모듈 자체의 바닥 판·벽은 유지하므로 건축 형태까지 연결하려면 모델 구조를 맞춰야 합니다. 유리·시점 의존 반사는 여전히 근사합니다.

모듈 규격

전체 GLB 씬 한 개가 모듈 한 개입니다. 기본 칸은 40×32m, 간격은 2m, 격자는 4×3칸입니다. 크기와 칸 수를 조정할 수 있으며 회전은 90° 단위입니다. 모듈은 바닥 중앙을 기준으로 놓고, 칸을 넘을 때만 균일하게 축소합니다. 모델의 가로·세로 비율을 바꾸거나 내부 방을 분리하지 않습니다.

보관·공개

파일당 48MiB, 한 번에 압축 해제된 파일 180MiB·100개까지 지원합니다. 렌더 결과는 임시 Actions artifact에서 저장소로 복사되므로 artifact 만료 후에도 남습니다. 현재 사이트 빌드는 관리자 코드만 포함하며, 업로드 원본·버전·격자 배치는 자동으로 공개 포트폴리오에 반영하지 않습니다. 공개 버전 선택과 배포는 별도 단계입니다.

공개 저장소의 표준 GitHub-hosted runner는 무료이며, 비공개 저장소는 계정별 무료 사용량을 사용합니다. 실제 한도와 초과 과금 설정은 GitHub Billing에서 확인하세요.
